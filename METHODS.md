# Methods and evidence contract

## Experimental evidence, not executable engine

The public package is intended to help independent readers inspect **what was supplied**, **what was expected** and **what native configurations and traffic decisions were observed**. Source code for RefinementEngine, control-specific native emitters, converter internals and orchestration is proprietary and not included. The topology contains data-plane startup/configuration and control-plane placeholder nodes; independent complete pipeline replay is not promised.

Original experimental input files are copied without alteration. Curated reference files extract declared expected predicates, source groups, action, locations, substitutions and traffic expectations from original independently specified oracles. `SOURCE_MAP.csv` carries the SHA-256 of the original oracle used, permitting comparisons with the separately retained full research record. The curated reference is not represented as a new independently authored oracle. Native rule text files contain the original observed configuration `stdout` without a command wrapper; the source file and checksum are recorded. HTTP observations are summaries of the corresponding recorded probe response; each row identifies the original evidence record and its SHA-256. Output summaries must not be interpreted as new physical measurements.

## RQ1

A1–A7 cover source IP, a destination-IP/TCP-port conjunction, WAF URL path and User-Agent, host-qualified outbound HTTP URL, proxy User-Agent, and domain/subdomain filtering. Use the `reference_expectations.json`, relevant network configuration, `native/deployed/` and traffic CSV together. For A2, check target denials plus same-IP/different-port and different-IP/same-port controls. For A3/A5, inspect the source-independent WAF rules and secondary-source probes, which test the intended application-layer predicates across distinct external sources, alongside matched/near-match behavior. For A4, distinguish the host-qualified URL and other-host same-path negative control. For A6, compare the native Squid `acl` and `http_access deny` blocks at both proxies with the matching, embedded, near-match and benign traffic probes from the five represented client populations. A7 shows both complete Squid `acl` + `http_access deny` blocks and tested five-source behavior, without claiming all other proxy clients were excluded. A1's original case verdict was explicitly preliminary; its observed data should be interpreted accordingly.

B1–B3 vary candidate controls/paths, with selected device/rule and representative enforcement observations. For B1, the independent reference enumerates three firewalls suitable for the tested direct TCP flow. The separate allocation benchmark preserves the four-candidate model trace, which also includes the abstract EgressProxy/Squid node; that node is not a literal proxy hop on the tested TCP route and was not selected. The benchmark's 1/1 greedy/ILP cardinalities are for this recorded model-level candidate set, not a physical suitability test of the proxy. In B3, the Guest Firewall becomes ineligible for allocation in the management model; its operational rules and routing remain unchanged. C1–C3 record unsupported/infeasible cases and their feasible controls; the original frozen reference-oracle files are retained unchanged and match the reported oracle hashes. The concise reference outcomes are derived reading views. Frozen originals may contain historical local workspace labels/source fingerprints but do not distribute the engine implementation. The allocation comparison uses eight recorded inputs (five operational; AS1–AS3 constructed abstract coverage instances); greedy/ILP median and 95th-percentile times cover **allocation only** over 25 repetitions, not full deployment latency.

The recorded offline benchmark used PuLP 3.3.2 with the CBC solver. The value `backend_version: 3.3.2` denotes the **PuLP package version**, not the CBC executable version. The benchmark code measures elapsed time with Python's `time.perf_counter_ns()` and converts nanoseconds to milliseconds. After one untimed warm-up for each method, it takes 25 measurements; `median_ms` is their median, while the value reported as `p95_ms` is selected from the sorted measurements at zero-based index `floor(0.95 × (n - 1))`, i.e., the 23rd observation for `n = 25` (without interpolation). The original retained results do not identify the benchmark host CPU or OS version, Python runtime version, or the CBC executable build; do not infer those from later replays. Thus absolute timings describe these recorded small offline instances and are not a portable end-to-end speed comparison. Raw repetition samples were not retained in this curated record.


## RQ2

`state_matrix.csv` lists S0–S9 and observed verified changes (five additions and five removals in total, excluding baseline rules). `states/Sn/lifecycle_state.json` contains owner tuples, active effective-rule identities, bindings, and the recorded operation history where available; native snapshots record device configuration independently of logical ownership. `traffic_observations.csv` aggregates actual HTTP statuses and return codes, with source hashes. Underlying operations and observations are not an exhaustive log of device commands.

The S4–S9 sequence proceeds from an independently verified restored S3 checkpoint. The C2 target and near-match probes in `RQ2/supporting_runs/2026-11-01_C2/` come from a separate supporting run of the same effective rule. The curated S6/S9 native configurations establish installation and removal; A2 and the supporting probes confirm predicate precision.

At S4, DOM-A and DOM-B are two distinct domain *indicator* identities sharing both proxy rules, but each proxy has multiple formal policy-instance owner tuples: HQ 8 and branch 2. At S5, after DOM-A withdrawal, HQ has 4 and branch 1. S6 retains the shared source-IP rule for SRC-B, withdraws UA, adds a qualified C2 rule; S7 removes the two proxy blocks only when DOM-B withdraws. S8 repeats unchanged reconciliation; S9 returns to zero active managed rules with baseline protections. The final S9 native snapshots show the post-removal configuration; the preceding device captures remain under `native/pre_removal/`, with source provenance in `SOURCE_MAP.csv`. The reverse-order campaign is separate. These assertions concern the observed sequential successful runs.

Actionability policy includes additional signals, but the controlled study exercises `to_ids=false` at two successive evaluations with `tau=2` for the specified indicator withdrawals. It does not assess natural threat-feed quality or all actionability-branch combinations.

## Integrity and limitations

Run `python3 verify_release.py` in the extracted repository directory; it checks file integrity, RQ1 allocation summary values against the 16-page manuscript, scenario presence, the A5/A7 complete native rule units, and selected S4/S5 owner cardinalities. The verifier does **not** rerun proprietary code or authenticate original experimental measurements from a trusted third party. Use original-source hashes as a map to the uncurated archival record, not as proof of independent execution.
